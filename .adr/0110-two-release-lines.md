# 0110: two release lines, Stable and Edge, and the state-shape rule

- **Status:** Accepted
- **Date:** 2026-10-18
- **Trail:** `bridge/update-line.ts` (the line record and the one resolver, `lineOffer`) · `cli/update.ts` (`planToTag`, `--line`, `--downgrade`, `keptStepDown`, `stampCheckout`, `lastStableKept`) · `bridge/update-action.ts` (`backVerdict`, `parseLineRequest`) · `bridge/server.ts` (`POST /api/update/back`, `GET`/`POST /api/update/line`) · `bridge/crew/follow.ts` (`X-Crew-Lead-Line`, `followGuards`) · `scripts/release-version.ts` (`--stamp`) · `web/src/components/release-line-card.tsx` · `bridge/state-shapes.test.ts` with `bridge/fixtures/last-stable/` · CREW_PROTOCOL.md §20, "Two release lines" · amends [ADR 0020](./0020-a-major-upgrade-is-consented-by-flag.md) (Stable is unchanged; Edge is a second line beside it) and [ADR 0016](./0016-updates-ride-the-operators-ssh.md)'s "no downgrade path" for two named cases

## Context

1.22.0 and 1.22.1 locked people out of the app when a regression slipped in (#468, #465). Every machine took the same build on the same day, so the first report came from everybody at once. Altan decided on 2026-10-17 and 2026-10-18 that a regression must reach volunteers first: a build lives for two or three days on machines whose owners asked for it, and Stable is cut from a build that lived that long with no new report.

## Decision

**Two release lines, per machine.** Stable takes strict releases only, as ADR 0020 always had it. Edge also takes `vX.Y.Z-edge.N` tags, which build like a release and publish as GitHub pre-releases with the same assets and a `collie-release.json` that says `line: "edge"`. GitHub's "latest" skips them. Altan cuts an Edge build by tag; the nightly legs are its gate. The version files in the tree stay `X.Y.Z`: the release runner, and the in-place updater on a Herdr-managed checkout, stamp the suffix into `herdr-plugin.toml`, `package.json` and `web/package.json` from the tag they check out, and mark those three files `assume-unchanged` so the tree stays clean and the build's `gitSha` carries no `-dirty`.

**The line is one record, and one resolver reads it.** `update-line.json` in the state directory holds the line, the builds this machine rolled back from, and the time and request id of the last change. It is a new file: an absent file reads as Stable with nothing rejected, which is what every machine was before. `lineOffer` is the only place that decides what a machine is offered, and the bridge's monitor, `collie update` and the phone all call it. On Edge the offer is the newest build above the installed one, strict releases and Edge builds together, in the same major; a final release supersedes its own Edge builds on both lines. A rejected build is never offered again. On Stable, a machine that runs an Edge build is offered strict releases only, and `back` names the newest strict release below it when nothing newer is offered.

**The switch installs nothing.** `POST /api/update/line` saves the line with a request id and answers the saved record; a replay of the same id with the same line answers the same receipt. The offer then changes, and the install is the normal update screen.

**A downgrade exists in exactly two cases.** A rollback (the kept build, as before) and a person-started switch back to Stable ("Go back now", `POST /api/update/back`, a run with a request id whose record carries `action: "switch"`). The updater takes a lower target only with `--downgrade`, which the bridge passes for those two runs and nothing else; `collie update --to-tag` without it keeps refusing. "Go back now" uses the kept Stable build when there is one: while a machine is on Edge, retention keeps the live build, the previous one, and the last Stable build, outside the count, until the machine is back on Stable. A rollback off an Edge build puts the machine on Stable and rejects that build. An Edge build that fails its own health check, and that the updater rolls back by itself, is rejected too, so it is not offered again at the next check; the line stays where the person set it. A member's own health gate is the same updater, so a member rejects the build the same way, and its follow guard refuses a rejected build in any run.

**The lead's line is the crew's line.** The lead sends `X-Crew-Lead-Line` beside `X-Crew-Lead-Release`, and `X-Crew-Lead-Release` now states an Edge build too. A member takes an Edge build only when the lead says `edge`, and a lower release only when the header names the lead's step, `rollback` or `switch`. A step down with a fresh run id skips the member's hourly limit once. The member takes the lead's line for its own. Both headers are additive-optional: an older member refuses an Edge build as not strict and never steps down, and an older lead sends no line, which reads as Stable.

**The state-shape rule.** A build never changes the shape of an existing state file in a way the latest Stable cannot read: new fields and new files only. A field is never removed, renamed, or given another JSON type, and an existing file is never replaced by another. "Go back now" and a rollback put the last Stable on a state directory the newer build wrote, and a Stable that cannot read its own pairing file locks its operator out, which is what the two lines exist to prevent.

`bridge/state-shapes.test.ts` holds the rule in CI. `bridge/fixtures/last-stable/` keeps state files as the last Stable writes them (`LAST_STABLE` names it; 1.22.6 today): `update.json`, `update-state.json`, `paired-devices.json` and `commands-recent.json`. For each, the head's own reader must read the fixture, and the head's own writer, fed what it read, must keep every key of the fixture at the same path with the same JSON type. A file that fails must be named in `UNREADABLE_BY_LAST_STABLE`, and the phone names those files before "Go back now". The list is empty, and the test also asserts that it stays empty: a non-empty list is a release decision for Altan, not a fix. After each Stable release, the fixtures are refreshed from that release's writers and `LAST_STABLE` moves.

**Cadence.** An Edge machine is told about a new build at the next check, not in the next digest; the 09:00 floor still holds. Stable keeps the digest windows. Release notes and the sidecar's CHANGELOG section are read by the base version, so `1.23.0-edge.2` shows the notes of `1.23.0`.

## Consequences

A regression reaches the machines whose owners chose Edge, and the way back is one confirm on the phone. Removing `update-line.json` restores the strict-release behaviour, and `collie update --rollback` is unchanged in what it does. The fixture set covers four files, not every file in the state directory; a change to another file's shape is held only by review until its fixture is added.
